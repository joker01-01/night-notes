# 决策记录 002：周场形态（2026-07-31）

> 状态：已接受 · 来源：grill-me 设计拷问会话（第一性原理推演） · 关联：PRODUCT.md §1 / §3 / §6 修订

## 背景

发布路线定案后，周场作为北极星（周场完成率）的核心载体，其具体形态需要确认。
输入材料：用户日常痕迹（自由写 / 日收束）+ 上周总结（周问 + 回答 + next_focus）。
约束：PRODUCT.md 宪法——打开优先、当时感不可事后补全、具体胜过正确、时间要有箭头、非考官审讯。

## 第一性原理

1. 人的长期记忆对「感受/分量」保真度极低——失真的是当时感，不是事件。
2. 周复盘的存在理由 = 在痕迹仍热时提取「本周最重的一件」并固化其分量，让信号指向下一步。
3. 三个动作：回忆（AI 可代劳）、识别（只有用户知道哪件重）、言说（必须是用户自己的话）。
4. AI 的改善方向：把复盘压到最小可完成单元——5 次点选 + 1 句自己的话，而不是替用户做复盘。

## 形态空间与裁决

| # | 形态 | 裁决 |
|---|------|------|
| 1 | 纯自由书写 | 否：解决不了「从零组织问题」，无周问即无核心资产 |
| 2 | 固定模板多问 | 否：与废案四问同构，压迫感 |
| 3 | 纯 AI 单问 | 否：日痕迹薄时问得泛 |
| 4 | 热身给料 + AI 单问 | 演进为 4′ |
| 4′ | **用户自选一件 + AI 就它问感受（采纳）** | 选择权在用户，问得准 |
| 5 | AI 导览 + 用户自选 | 被 4′ 吸收（自选即导览） |
| 6 | 多轮对话 | 否：拖长，打击完成率 |
| 7 | AI 周报先行 + 用户校对 | 否：一键大周报废案 |

## 主路径（硬）

AI 记忆管家（痕迹聚类候选 + 上周承接对照）→ 用户自选本周最重一件（可自加）→ 点选情绪表情（6-8 个预选，可「说不清/跳过」）→ AI 生成一个温柔周问（只问感受/分量）→ 用户一句话作答（可语音）→ AI 收束草稿（echo + 2-3 个 next_focus 候选）→ 用户点选/改写确认。

## 关键决策

| 分支 | 决策 | 理由 |
|------|------|------|
| 选择化 | 「写累选易」：除作答外全部为点选 | 认知成本低一个数量级；直接服务北极星 |
| AI 分工 | 记忆管家 / 感受主人：AI 只做检索 / 对照 / 出题 / 收束草稿；**永不代写回答、永不先出总结** | 言说环节代笔则当时感失真（第一性链条断裂）；AI 概览抢先于用户反思，会压制自己的感受 |
| 情绪表情 | 单表情；预选集 8 个 + 跳过（🤩期待 / 😊满足 / 🙂还好 / 😮💨吃力 / 😣堵住 / 😤不甘 / 🥺难过 / 🤔说不清）；不设分量滑杆 | 一个控件就好；分量从回答里长出来；「跳过」与「说不清」分开——🤔 是一种态度，跳过是没有态度 |
| 上周信号 | 承接式：问「分量变没变」，不问「做了没」；验证只做 AI 隐形上下文 | 验证式是考勤机 / 愧疚引擎；承接式保持感受框架且自然包含隐式验证 |
| 提纲热身 | 退役（三个空格被「自选一件」取代） | 不再出现在主路径 |
| 完成口径 | 留下「周问 + 回答」即完成；点选 / 表情 / 收束不计入 | 北极星口径不变 |
| 弹性热窗 | 周日开放，周一/周二可完整补做；周三起降级「只收不问」；不追债，降级周不计入完成率 | 错过是常态；凉了不硬问；保住下次打开的门 |
| 收束 | AI 出 echo + 2-3 个 next_focus 候选 + note（可空）；用户点选或改写后落库；可「再收一下」 | 极短；方向候选化；note 保留但不欠 |

## 数据模型变更

- `weekly_reviews` 新增 `followup_emotion TEXT DEFAULT ''`（情绪表情 / 说不清标记），Flutter Drift schema 落地。
- 周场候选、next_focus 候选为 UI 态，默认不落库（如需调试可存 JSON，待实现定）。

## 表情预选集（最终）

🤩 期待 / 😊 满足 / 🙂 还好 / 😮💨 吃力 / 😣 堵住 / 😤 不甘 / 🥺 难过 / 🤔 说不清；另设「跳过」文本按钮（不选任何表情直接进下一步）。每个表情配一个字标注。

## 弹性热窗

周日开放（本地通知）；周一、周二可完整补做；周三起自动降级为「只收不问」——不再生成周问，页面只留一行「这周痕迹凉了，不硬问了。想收就写一句，不收也行。」+「先这样」按钮。不追债、不惩罚；降级周不计入完成率；下周日照常开新周。

## Prompt 定稿

### 周问（承接式 + 表情引子）

```text
你在帮用户做每周一次的「和自己谈谈」：私密、短、清醒。不是周报作者，不是考官，不是犀利教练。
用户已经自己选出本周最占心力的一件事，并选了一个情绪表情。你的任务：围绕这件事，只产出【一个】
值得坐下来回答的问题，把话问回他自己。

输入：
- 【用户自选】本周最占心力的一件事
- 【情绪表情】用户对这一件的当下感觉（含标注）
- 【上周承接】上周他自己留下的周问/回答/下一步（可能为空）
- 【本周痕迹】近七日记录（仅供参考，不另挑主题）

要求：
1. 问题必须锚定用户自选的那件事，不得另挑主题、不得重新排序他的选择。
2. 表情是切入点，但只定方向不逼问：重分量（吃力/堵住/不甘/难过）往「为什么这么重」问；
   轻分量（期待/满足/还好）往「它给了你什么」问；说不清往「哪一层说不清」问。
   若用户选了「还好/平静」，允许问题只是轻轻确认，不逼出情绪。
3. 承接式：若上周信号与这件事相关，问「分量变没变」，不做「做了没」的对账；
   若无关，上周信号仅作氛围参考，不硬扯。
4. 点名这件事（可结合痕迹里的细节），不用「这件事」代称；语气温柔、具体、不说教、不给答案。
5. 禁止：周总结、复盘列表、一次问两件事、鸡汤、「你应该」。

输出：仅问题本身，无前缀无客套。
```

### 收束（echo + 候选）

```text
用户刚回答了本周那个周问（围绕他自己选的那件事）。做极短收束，不要重写一篇周总结。
只返回 JSON，键严格为 echo、next_focus_candidates、note（note 可为空字符串）：

- echo：1-2 句如实反映他的回答（可点出表情方向），不评价、不借机摘要整周。
- next_focus_candidates：恰好 2-3 个候选，每个是一句【可动手的具体下一步】，来自回答里
  露出的方向；若回答没露出任何方向，数组只放一条：「本周先不硬定下一件」。
  禁止替他发明宏大计划，禁止「继续推进X」这类空话。
- note：一句留给自己的话，短，像他自己写的；可为空。

禁止鸡汤、禁止「你应该」、禁止整周做了什么清单体。不要 Markdown 代码块或其它键。
```
